# 1.8 Client OS Network Verification & Troubleshooting

## Operating System Network Commands

| Operational Verification | Windows Command | Linux (iproute2) Command | macOS Command |
|---|---|---|---|
| **IP, Mask & Interface** | `ipconfig` | `ip addr` (or `ip a`) | `ifconfig <interface>` |
| **MAC Address & DHCP/DNS**| `ipconfig /all` | `ip link` / `cat /etc/resolv.conf` | `networksetup -getinfo Wi-Fi` |
| **Clear DNS Cache** | `ipconfig /flushdns` | `systemd-resolve --flush-caches` | `dscacheutil -flushcache` |
| **Renew DHCP Lease** | `ipconfig /release && renew` | `dhclient -r && dhclient` | `sudo ipconfig set <if> DHCP`|
| **Display Local ARP Cache** | `arp -a` | `ip neigh` | `arp -a` |
| **Display Routing Table** | `route print` / `netstat -r` | `ip route` (or `ip r`) | `netstat -nr` / `route -n get default` |
| **Active Sockets & Ports** | `netstat -ano` | `ss -tulpn` | `netstat -an` / `lsof -i` |

* **[TRAP]** **APIPA Identification:** Windows IP in `169.254.X.X` with no Default Gateway means the client failed to reach a DHCP server.

## Troubleshooting Scenarios: Cause ↳ Symptom ↳ Fix

```
Troubleshooting Chains:
*  Scenario: Incorrect Default Gateway configured on client
  ↳  Symptom: Host communicates with local subnet devices; cannot ping external IPs or Internet.
  ↳  Fix: Match host default gateway IP to the local router SVI/interface in the same subnet.

*  Scenario: Missing or Unreachable DNS Server
  ↳  Symptom: Pinging numerical external IP (8.8.8.8) succeeds; domain names (google.com) fail.
  ↳  Fix: Verify DNS IP under "ipconfig /all" or check DHCP Option 6.

*  Scenario: Incorrect Subnet Mask on Client
  ↳  Symptom: Local destinations treated as remote (sent to gateway), or remote destinations treated as local (failing ARP).
  ↳  Fix: Correct mask to match the operational prefix of the subnet.

*  Scenario: Duplicate IP Address on Segment
  ↳  Symptom: Intermittent packet loss, flapping CAM table entries on switchports, OS warning popups.
  ↳  Fix: Run Gratuitous ARP / check switch CAM address-table to identify conflicting MAC.
```
