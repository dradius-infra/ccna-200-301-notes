# 1.2 Physical Media, Cabling, Ethernet Standards & Diagnostics

## Mental Models: Duplex & Collisions
* **Half-Duplex:** Walkie-Talkies. You press the button to talk; if both speak at the same time, audio is garbled (collision).
* **Full-Duplex:** Telephone Call. Dedicated earphone and mouthpiece; both sides talk and listen simultaneously without interference.

---

## Media Access & Duplex Comparison

| Duplex Mode | Collisions Possible? | Method Used | Physical Media Requirement |
|---|---|---|---|
| **Half-Duplex** | **Yes** (Shared wire) | **CSMA/CD** | Shared bus, legacy Hubs, or duplex-mismatched links |
| **Full-Duplex** | **No** (Collisions impossible)| None (CSMA/CD off) | Dedicated TX/RX wire pairs (Switch to Switch/Host) |

```
CSMA/CD Logic:
[ Listen to wire ] ---> [ Idle? Transmit ]
                            |
           [ Collision detected by concurrent senders ]
                            |
                     [ Jam Signal sent ]
                            |
      [ Random Truncated Exponential Backoff Timer invokes ]
                            |
                   [ Retry Transmission ]
```

## Switch Forwarding Architectures

| Switching Method | Latency Level | Internal Mechanism | Error Handling |
|---|---|---|---|
| **Store-and-Forward** | Highest | Reads full frame, validates FCS/CRC | **Drops all corrupt frames & runts** |
| **Cut-Through** | Lowest | Reads only first **6 bytes** (Dest MAC) | Forwards runts and corrupt frames |
| **Fragment-Free** | Moderate | Reads first **64 bytes** (Collision window)| Discards collision fragments/runts |

## Interface Line States Troubleshooting

```
Troubleshooting Chains:
*  State: Status administratively down / Protocol down
  ↳  Root Cause: Port manually turned off.
  ↳  Action: Run "no shutdown" under interface configuration mode.

*  State: Status down / Protocol down
  ↳  Root Cause: Layer 1 physical break.
  ↳  Action: Check cable unplugged, damaged pins, remote switchport power, bad SFP transceiver.

*  State: Status up / Protocol down
  ↳  Root Cause: Layer 2 framing or configuration mismatch.
  ↳  Action: Check encapsulation mismatch, keepalive failure, native VLAN mismatch, duplex mismatch.

*  State: Status up / Protocol up
  ↳  Root Cause: Fully operational L1 physical and L2 data-link state.
```

## Interface Counters & Diagnostics (`show interfaces`)

| Diagnostic Counter | Frame Size / Boundary | Root Cause |
|---|---|---|
| **Late Collisions** | **$> 64\text{ bytes}$** (512 bits) | **Duplex Mismatch** or cable run exceeding 100 meters |
| **Runts** | **$< 64\text{ bytes}$** | Collisions, electrical noise, bad cable crimping |
| **Giants** | **$> 1518\text{ bytes}$** (non-jumbo) | Host sending oversized frames / untagged baby-giants |
| **CRC / FCS Errors** | Frame checksum failure | Faulty copper termination, electromagnetic noise (EMI), bad transceiver |
| **Input Drops** | Ingress buffer full | Switch ASIC / CPU overloaded; cannot empty buffer fast enough |
| **Output Drops** | Egress buffer full | Link congestion; egress pipe smaller than ingress bursts |

* **[TRAP]** **Auto-Negotiation Failure Rule:**
  * Switch Port 1: Hardcoded `speed 100 / duplex full`.
  * Switch Port 2: Configured for `auto`.
  * **Result:** Port 2 senses 100 Mbps electrically, but **duplex auto-negotiation fails completely**. Port 2 defaults to **Half-Duplex** (IEEE standard).
  * **Consequence:** Duplex Mismatch $\to$ Late Collisions on Port 2 (Half), CRC errors on Port 1 (Full).

### Authentic CLI Snippet: Diagnosing Duplex Mismatch
```text
SW1# show interfaces gigabitEthernet 0/1
GigabitEthernet0/1 is up, line protocol is up 
  Half-duplex, 100Mb/s, link type is auto, media type is 10/100/1000BaseTX
  Input queue: 0/75/0/0 (size/max/drops/flushes); Total output drops: 0
  12480 packets input, 1024880 bytes, 0 no buffer
  Received 280 broadcasts (120 multicasts)
  0 runts, 0 giants, 0 throttles
  0 input errors, 0 CRC, 0 frame, 0 overrun, 0 ignored
  842 late collision, 1202 deferred, 0 lost carrier   <-- [BOOM: Duplex Mismatch on this port!]
```

## Copper Cabling (Twisted Pair)

| Cable Category | Max Bandwidth Frequency | Supported Data Rate | Maximum Certified Distance |
|---|---|---|---|
| **Cat5e** | 100 MHz | 1 Gbps | 100 meters |
| **Cat6** | 250 MHz | 1 Gbps (10 Gbps up to 55m) | 100 meters (55m for 10G) |
| **Cat6a** | 500 MHz | 10 Gbps | 100 meters |

* **[EXAM-FACT]** **UTP vs. STP:**
  * **UTP:** Relies strictly on the geometric **cancellation effect** of tightly twisted pairs to negate EMI.
  * **STP:** Encased in outer foil shielding and braided pair shields; mandatory for high-EMI industrial machinery; requires physical earth grounding.

### Pinout Wiring Schemes

```
T568A: [W-Grn, Grn, W-Orn, Blu, W-Blu, Orn, W-Brn, Brn]
T568B: [W-Orn, Orn, W-Grn, Blu, W-Blu, Grn, W-Brn, Brn]
```

| Cable Type | End A Wiring | End B Wiring | Device Connection Use-Cases |
|---|---|---|---|
| **Straight-Through** | T568B | T568B (or both A) | Differing layers: Switch-to-Host, Switch-to-Router |
| **Crossover** | T568A | T568B | Like devices: Switch-to-Switch, PC-to-PC, **Router-to-PC** |
| **Rollover** | Pin 1 through 8 | Pin 8 through 1 | Serial RJ45 Console terminal access |

* **[EXAM-FACT]** **Fast Ethernet Crossover (10/100):** Swaps pairs 1/2 with 3/6 ($1 \leftrightarrow 3$ and $2 \leftrightarrow 6$). Pins 4, 5, 7, 8 remain straight.
* **[EXAM-FACT]** **Gigabit Ethernet Crossover (1000BASE-T):** Crosses all four pairs: $1 \leftrightarrow 3$, $2 \leftrightarrow 6$, $4 \leftrightarrow 7$, $5 \leftrightarrow 8$.
* **[EXAM-FACT]** **Auto-MDIX:** Automatically detects and internally flips transmit and receive pairs (requires speed and duplex set to `auto`).

## Fiber Optic Cabling & Transceivers

| Fiber Type | Core Diameter | Light Source | Operating Wavelengths | Dispersion Type | Distance Span |
|---|---|---|---|---|---|
| **Single-Mode (SMF)**| ~9 µm | **Laser Diode** | 1310 nm, 1550 nm | Chromatic only (Zero modal) | Up to 40+ km |
| **Multi-Mode (MMF)** | 50–62.5 µm | **LED / VCSEL** | 850 nm, 1300 nm | **Modal dispersion** (light bounces)| Up to 300–550m |

* **[EXAM-FACT]** **WDM (Wavelength-Division Multiplexing):** Transmits multiple distinct data streams over a single fiber strand by multiplexing different colors (wavelengths) of light (CWDM and DWDM).
* **[EXAM-FACT]** **Fiber Connectors:**
  * **LC:** Small form-factor push-pull latch (standard for SFP/SFP+).
  * **SC:** Square push-pull connector.
  * **ST:** Round bayonet twist-lock connector.
  * **MPO / MTP:** Multi-fiber ribbon connector terminating 12 to 24 fibers (40G/100G QSFP optics).

## Power over Ethernet (PoE) Standards & Pin Allocations

| Standard | Name | Power at PSE | Power at PD | Wire Pairs Used | Conductor Pin Allocation |
|---|---|---|---|---|---|
| **802.3af** | PoE (Type 1) | 15.4 W | 12.95 W | 2 Pairs | Alt A (Pins 1,2,3,6) OR Alt B (Pins 4,5,7,8) |
| **802.3at** | PoE+ (Type 2) | 30.0 W | 25.5 W | 2 Pairs | Alt A (Pins 1,2,3,6) OR Alt B (Pins 4,5,7,8) |
| **802.3bt** | PoE++ (Type 3)| 60.0 W | 51.0 W | 2 or 4 Pairs | Up to 60W delivery |
| **802.3bt** | PoE++ (Type 4)| **90–100 W** | **71.3 W** | **4 Pairs (Mandatory)**| Uses all 8 wires to avoid melting insulation |

* **[EXAM-FACT]** **PSE vs. PD:**
  * **PSE (Power Sourcing Equipment):** The switch port or midspan injector delivering power.
  * **PD (Powered Device):** The client hardware drawing power (IP Phone, AP, Pan-Tilt-Zoom camera).
* **[EXAM-FACT]** **Negotiation:** Initial physical loop resistance check is followed by fine-grained wattage allocation negotiated via **CDP** (Cisco) or **LLDP-MED** (IEEE open standard).
