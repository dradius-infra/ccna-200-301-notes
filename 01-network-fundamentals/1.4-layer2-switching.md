# 1.4 Layer 2 Switching, Framing & Addressing

## 🧠 Mental Models: Broadcast vs. Unicast ARP
* **ARP Request (Broadcast):** Standing up in a crowded room and shouting: *"Who is Bob? Tell Alice!"* Everyone stops and listens, but only Bob cares.
* **ARP Reply (Unicast):** Bob walks directly over to Alice and whispers: *"I am Bob, here is my ID card (MAC address)."*

## Ethernet Frame Breakdown (IEEE 802.3)

```
+----------+-----+----------+----------+-----------+----------------+---------+
| Preamble | SFD | Dest MAC | Src MAC  | Type/Len  |    Payload     |   FCS   |
|  7 bytes |  1B |  6 bytes |  6 bytes |  2 bytes  | 46-1500 bytes  | 4 bytes |
+----------+-----+----------+----------+-----------+----------------+---------+
```

| Field Name | Size (Bytes) | Exact Purpose |
|---|---|---|
| **Preamble** | 7 bytes | 56 alternating bits (`10101010...`) for clock synchronization |
| **SFD (Start Frame Delimiter)**| 1 byte | Byte `10101011` indicating that Destination MAC immediately follows |
| **Destination MAC** | 6 bytes | Target Layer 2 physical address (Unicast, Multicast, or Broadcast) |
| **Source MAC** | 6 bytes | Originating Layer 2 physical address (Always Unicast) |
| **EtherType / Length** | 2 bytes | Upper layer identification: $\ge 1536$ (`0x0600`) = Type field |
| **Payload** | 46–1500 bytes | Encapsulated L3 packet (Padded with 0s if payload $< 46\text{ bytes}$) |
| **FCS** | 4 bytes | Cyclic Redundancy Check (CRC) checksum value for error detection |

* ⚡ **[FAST-MATH]** **EtherType Hex Codes:**
  * `0x0800` $\to$ IPv4
  * `0x86DD` $\to$ IPv6
  * `0x0806` $\to$ ARP
  * `0x8100` $\to$ 802.1Q VLAN Tag (Inserts 4 bytes before standard EtherType)
* ⚡ **[FAST-MATH]** **Frame Size Boundaries:**
  * Minimum size: **64 bytes** (Payloads under 46 bytes are padded).
  * Standard maximum size: **1518 bytes** (or **1522 bytes** with 802.1Q tag).
  * Non-standard frames: $< 64\text{ bytes}$ = **Runts**; $> 1518\text{ bytes}$ = **Giants**.

## MAC Addressing Anatomy (EUI-48)

```
48-Bit MAC Address Anatomy:
[      24 Bits OUI      ] [   24 Bits Vendor Serial   ]
[ Byte 1 ] [ Byte 2-3 ]   [ Byte 4 ] [ Byte 5 ] [ Byte 6 ]
    |
    +--> Bit 0 (I/G Bit): 0 = Unicast, 1 = Group (Multicast/Broadcast)
    +--> Bit 1 (U/L Bit): 0 = Globally Unique (IEEE), 1 = Locally Administered
```

| Address Type | L2 MAC Destination Pattern | Intended Receiver Scope |
|---|---|---|
| **Unicast** | Standard host MAC (I/G bit = 0) | Single specific NIC interface |
| **Broadcast** | `FF:FF:FF:FF:FF:FF` (All 48 bits = 1) | Every active host in the broadcast domain (VLAN) |
| **IPv4 Multicast** | Always begins with **`01:00:5E`** | Mapped to lowest 23 bits of target IPv4 multicast IP |
| **IPv6 Multicast** | Always begins with **`33:33`** | Mapped to lowest 32 bits of target IPv6 multicast IP |

## Collision vs. Broadcast Domains

| Domain Scope | Boundary Device | What Blocks/Isolates It? | Default State |
|---|---|---|---|
| **Collision Domain** | Switch / Bridge / Router | Every single Full-Duplex switchport | Hubs = 1 shared collision domain across all ports |
| **Broadcast Domain** | Router / Layer 3 Switch | Router physical interface or Layer 2 VLAN | Unmanaged Switch = 1 single broadcast domain |

## Layer 2 Switching Logic (CAM Table Processing)

```
Incoming Frame Handling:
[ Ingress Frame arrives ]
       |
       v
[ Inspect Source MAC ] -----> If NOT in CAM table: Add MAC, port, and VLAN (Age timer: 300s)
                              If ALREADY in CAM table: Refresh aging timer
       |
       v
[ Inspect Destination MAC ]
       |---> Known Unicast    --> Forward out the specific mapped interface ONLY
       |---> Unknown Unicast  --> FLOOD frame out all ports in VLAN (Except ingress port)
       |---> Broadcast / Multi--> FLOOD frame out all ports in VLAN (Except ingress port)
       |---> Destination = Port-> FILTER (Drop) frame (Destination is on the incoming segment)
```

* 🚨 **[TRAP]** **MAC Flooding Attack:** Attacker exhausts CAM table memory with thousands of bogus source MACs. The switch fails into a **fail-open** hub mode, flooding all unicast traffic out every port. Fix: Enable **Port Security**.

## Address Resolution Protocol (ARP)

| ARP Message Type | Layer 2 Encapsulation | Layer 3 Destination IP | Functional Purpose |
|---|---|---|---|
| **ARP Request** | **Broadcast** (`FF:FF:FF:FF:FF:FF`) | Target Unicast IP | "Who has this IP? Tell my MAC." |
| **ARP Reply** | **Unicast** (Target MAC) | Requesting Sender IP | "I have that IP, here is my MAC." |
| **Gratuitous ARP (GARP)**| **Broadcast** | Sender's OWN IP | Announces IP ownership; detects IP conflicts |
| **Proxy ARP** | **Unicast** (Router MAC) | Local Requesting Host | Router replies with its own MAC for remote subnets |

## Discovery Protocols: CDP vs. LLDP

| Feature Parameter | CDP (Cisco Discovery Protocol) | LLDP (Link Layer Discovery Protocol) |
|---|---|---|
| **Standard Type** | Cisco Proprietary | IEEE Open Standard (**802.1AB**) |
| **Default State** | Enabled by default on Cisco hardware | Disabled by default on some platforms |
| **L2 Multicast Address** | `01:00:0C:CC:CC:CC` | `01:80:C2:00:00:0E` |
| **Transmit Interval** | **60 seconds** | **30 seconds** |
| **Holdtime Timer** | **180 seconds** | **120 seconds** |
| **Data Payload Format** | Proprietary TLVs | Standard TLVs (Type-Length-Value) |
