# 1.1 Network Architecture, Topologies, Models & Planes

## Mental Models: The City Traffic System
* **Data Plane:** The asphalt roads, bridges, and trucks carrying cargo (user data packets).
* **Control Plane:** The traffic lights, road signs, and GPS navigation recalculating routes (OSPF, ARP, STP).
* **Management Plane:** The city planner's maintenance radio tuning the traffic cameras and dispatch logs (SSH, SNMP).

---

## Network Architectural Planes

| Plane | Core Role | Forwarding Impact | Key Protocols / Tables | Hardware Level |
|---|---|---|---|---|
| **Data Plane** | Moves user traffic ingress $\to$ egress | Direct user forwarding | FIB, Adjacency Table, ACL filtering, NAT, QoS policing | ASICs, TCAM, CEF |
| **Control Plane** | Populates Data Plane forwarding tables | Path calculation & signaling | OSPF, EIGRP, BGP, STP, ARP, IPv6 NDP, CDP/LLDP | CPU / RAM (Software) |
| **Management Plane** | Device access, config & monitoring | Administrative access only | SSH, Telnet, SNMPv2c/v3, Syslog, NTP, RESTCONF, GUI | CPU / RAM (Software) |

```
       +------------------------------------------------+
       |   Management Plane (SSH, SNMP, Syslog, GUI)   |
       +------------------------------------------------+
       +------------------------------------------------+
       |     Control Plane (OSPF, EIGRP, STP, ARP)      |
       +------------------------------------------------+
                               | Populates FIB & TCAM
                               v
       +------------------------------------------------+
       | Data Plane (ASICs, TCAM, CEF FIB / Adjacency)  |
       +------------------------------------------------+
```

* **[TRAP]** **Data Plane vs. Control Plane Exception Handling:** 
  * The **Data Plane (ASICs/TCAM)** only handles fast, uninterrupted **transit traffic** (forwarding user packets). It cannot generate new control packets or handle protocol exceptions.
  * The **Control Plane (CPU)** handles all **exceptions and device-generated packets**. If a packet cannot be forwarded via hardware (e.g., TTL expires $\le 1$, IP Options enabled, or ARP missing), it is punted to the CPU. The CPU/Control Plane is exclusively responsible for generating and transmitting control messages, such as **ICMP Time Exceeded (Type 11)**.

## Management Methods: In-Band vs. Out-of-Band (OOB)

| Method | Transport Medium | IP Routing Dependent? | Risk Factor |
|---|---|---|---|
| **In-Band** | Standard production data links | **Yes** (VTY lines: SSH/Telnet) | Fails completely during link crashes or broadcast storms |
| **Out-of-Band (OOB)** | Isolated management link/port | **No** (Console port, AUX, dedicated Mgmt 0/0) | Survives complete network down-states |

*  **[EXAM-FACT]** Serial Console RS-232 Default Parameters: **9600-8-N-1**
  * Speed: **9600 bps**
  * Data bits: **8**
  * Parity: **None**
  * Stop bits: **1**
  * Flow control: **None**

## SDN & Controller-Based Architecture

```
[ Application / Scripts ]  <-- (Python, Ansible, Dashboards)
           |
       [ Northbound APIs ]  <-- (RESTful / JSON)
           |
   [ SDN Controller ]     <-- (Cisco Catalyst Center / Centralized Control Plane)
           |
       [ Southbound APIs ]  <-- (OpenFlow, NETCONF, RESTCONF, gRPC, OnePK)
           |
  [ Physical Data Plane ]  <-- (Switches / Routers - ASICs only)
```

*  **[EXAM-FACT]** **Decoupling principle:** Control plane is removed from distributed edge hardware and centralized in the controller. Physical devices keep only the Data Plane.
*  **[EXAM-FACT]** **Southbound APIs (SBIs):** Connect Controller down to devices (OpenFlow, NETCONF via SSH/XML, RESTCONF via HTTP/JSON/XML, OnePK, gRPC).
*  **[EXAM-FACT]** **Northbound APIs (NBIs):** Connect Controller up to business apps/scripts (RESTful APIs with JSON payloads).

## Campus & Data Center Design Models

| Model | Structural Layers | Primary Objective | Traffic Focus |
|---|---|---|---|
| **Three-Tier Campus** | Core $\to$ Distribution $\to$ Access | Modularity & physical isolation | North-South |
| **Two-Tier (Collapsed Core)**| Core + Distribution merged $\to$ Access | Lower cost & footprint for SMBs | North-South |
| **Spine-Leaf Fabric** | Spine $\to$ Leaf (2-hop matrix) | Non-blocking server clusters | East-West |

```
Spine-Leaf Matrix:
Spine Layer:      [ Spine 1 ] =========== [ Spine 2 ]  (Spines NEVER connect to Spines!)
                    /       \             /       \
Leaf Layer:     [ Leaf 1 ]   [ Leaf 2 ]  [ Leaf 3 ]    (Leafs NEVER connect to Leafs!)
                    |            |           |
Endpoints:      [ Server ]   [ Server ]  [ Storage ]
```

* **[TRAP]** **Core Layer:** Strict packet switching only. **Never run CPU-heavy ACLs**, QoS policing, or VLAN terminations (SVIs) here.
* **[EXAM-FACT]** **Distribution Layer:** Policy routing, ACL filtering, QoS enforcement, and SVI broadcast domain termination.
* **[EXAM-FACT]** **Access Layer:** End-user ports. Enforces Port Security, 802.1X identity, PoE delivery, and PortFast/BPDU Guard.
* **[FAST-MATH]** **Spine-Leaf Hop Count:** Always exactly **2 hops** between any two servers (Leaf $\to$ Spine $\to$ Leaf).

## WAN Topologies & SOHO

| Topology | Link Redundancy | Cable / Circuit Count | Failure Impact |
|---|---|---|---|
| **Point-to-Point (P2P)** | None (single circuit) | 1 dedicated line | Complete site isolation |
| **Hub-and-Spoke (Star)** | Centralized dependency | $N - 1$ links | Hub failure disconnects all spokes |
| **Full Mesh** | Absolute maximum | $\frac{N(N-1)}{2}$ links | Extremely resilient, highest cost |
| **Partial Mesh** | Balanced priority | Variable | Redundancy for critical links only |

* **[FAST-MATH]** Links required for Full Mesh: $\mathbf{\frac{N(N-1)}{2}}$.
* **[TRAP]** **Hub-and-Spoke Spoke Transit:** Direct communication between spokes requires **hair-pinning** through the central hub.
* **[EXAM-FACT]** **Hub-and-Spoke Design Trade-off:** Lowest circuit cost ($N-1$ links) and centralized security policy, but introduces higher latency (due to hair-pinning) and a Single Point of Failure at the central hub.
* **[EXAM-FACT]** **SOHO Architecture:** Single integrated hardware chassis uniting WAN router, PPPoE/DHCP client, NAT overload (PAT), switch ports, and Wi-Fi AP.

## Virtualization: Hypervisors, Containers & NFV

| Virtualization Type | Host OS Dependency | Startup Latency | Resource Overhead |
|---|---|---|---|
| **Type 1 (Bare-Metal)** | **None** (Direct hardware installation) | Fast | Minimal (Enterprise grade: ESXi, KVM) |
| **Type 2 (Hosted)** | **Yes** (Runs on top of Host OS) | Moderate | High (Workstation, VirtualBox) |
| **Containers** | Shares Host OS Kernel | Instant (Seconds) | Micro (Docker isolates user-space) |

* **[EXAM-FACT]** **vSwitch Data Plane:** VMs on the same hypervisor and same VLAN switch **directly inside system RAM**. Traffic never touches the physical NIC (pNIC).
* **[EXAM-FACT]** **VLAN Tagging in vSwitch:**
  * **EST:** Tagging occurs upstream on the physical switch port.
  * **VST:** Tagging performed by the vSwitch before leaving the physical host.
  * **VGT:** Tagging performed directly inside the VM / Guest OS.
* **[EXAM-FACT]** **NFV & VNFs:** Replaces dedicated hardware appliances with Virtual Network Functions (e.g., Cisco ASAv, CSR1000v, Catalyst 8000v).
* **[EXAM-FACT]** **VRF (Virtual Routing and Forwarding):** Coexisting isolated routing tables on one router; supports overlapping IP address spaces.

## Network Device Roles & Intelligence

| Device Role | Forwarding Layer | Forwarding Basis | Key Security / Operations |
|---|---|---|---|
| **Router** | Layer 3 | IP Routing Table | Terminates broadcast domains |
| **L2 Switch** | Layer 2 | Dynamic CAM (MAC) Table | Isolates collision domains |
| **Multilayer Switch** | Layer 2 + Layer 3 | Hardware CEF (FIB/Adjacency) | Wire-speed inter-VLAN routing |
| **NGFW** | Layer 3 to Layer 7 | Stateful packet + App inspection | AVC, TLS/SSL decryption, IPS |
| **NGIPS** | Layer 2 / Inline | Signature & heuristic analysis | Deep Packet Inspection (DPI) |
| **SDN Controller** | Control Plane | Centralized policy orchestration | Cisco Catalyst Center / WLC |

* **[EXAM-FACT]** **Cisco AI Assistant:** Generative AI / LLM integration in management engines to query telemetry, auto-generate CLI syntax, and isolate Root Cause Analysis (RCA).

## Cisco Device Memory & Boot Process

| Memory Type | Persistence | Content Stored | Exam Focus |
|---|---|---|---|
| **ROM** | Non-volatile (Permanent) | POST microcode, Bootstrap, ROMMON | Low-level hardware diagnostic recovery |
| **Flash** | Non-volatile (Persists) | Cisco IOS / IOS-XE system images (.bin) | Main operating system filesystem |
| **NVRAM** | Non-volatile (Persists) | **startup-config**, Configuration Register | Retains config across reboots |
| **RAM** | **Volatile** (Wiped on reboot) | **running-config**, ARP, MAC table, FIB | Active operational memory |

### Boot Sequence Step-by-Step

```
[ Power On ] 
     |
     v
[ 1. POST ] executes from ROM (Validates CPU, RAM, interfaces)
     |
     v
[ 2. Bootstrap ] loads from ROM
     |
     v
[ 3. Read Config Register ]
     |---> 0x2102: Normal boot (Loads IOS from Flash, startup-config from NVRAM)
     |---> 0x2142: Password Recovery (Ignores NVRAM startup-config completely)
     |
     v
[ 4. Load IOS ] from Flash into RAM
     |
     v
[ 5. Load Config ] copies startup-config (NVRAM) into running-config (RAM)
     (No startup-config found? Starts System Configuration Dialog Wizard)
```

## Network Performance Metrics

| Metric | Definition | Critical Real-Time Threshold | Trigger / Cause |
|---|---|---|---|
| **Latency** | End-to-end packet transit delay | Path dependent | Propagation, serialization, queuing delay |
| **Jitter** | Delay variation between packets | **$< 30\text{ ms}$** | Uneven buffer queuing during congestion |
| **Packet Loss** | Dropped packet percentage | **$< 1\%$** | Buffer exhaustion, physical FCS errors |

* **[EXAM-FACT]** **Latency Components:**
  * **Propagation Delay:** Physical speed of light through glass or copper.
  * **Serialization Delay:** Time required to encode bits onto the physical media.
  * **Queuing Delay:** Time the packet sits waiting inside interface memory buffers.
  * **Processing Delay:** Time the router CPU/ASIC takes to parse headers and make FIB lookups.
